(4) 分布式训练 · (i)

训练的显存与算力账

分布式训练里的每个选择，都是在两本账之间权衡：一步训练要做多少次浮点运算，要占多少显存。这一页把两本账算清楚，再用 roofline 说明为什么同样的 FLOPs，有的算子能跑满 GPU，有的连十分之一都跑不到。后面几页讲的精度、ZeRO 和各种并行，都是在这两本账上省显存或省时间。

GPU 的存储层级

存储层级：离计算单元越近的存储越快、越小。一次运算的数据要从 HBM（显存）经 L2 缓存搬进每个 SM 的共享内存（SMEM）和寄存器，Tensor Core 才能用它做矩阵乘。

一块 GPU 由上百个 SM（streaming multiprocessor）组成。每个 SM 里有 Tensor Core（专做小矩阵块的乘加 $D=AB+C$）、普通 CUDA core 和特殊函数单元（算 exp 等）。峰值算力只有矩阵乘能拿到：H100 SXM 的 BF16 Tensor Core 稠密峰值 989 TFLOPS，非 Tensor Core 的 FP32 只有 67 TFLOPS，差约 15 倍。

矩阵乘为什么能跑满：分块

矩阵乘 $C=AB$ 的每个元素都要读 A 的一整行和 B 的一整列，直接从 HBM 读会把带宽耗光。GEMM kernel 的做法是：每个线程块负责 C 的一个 $T\times T$ 块，沿 $k$ 方向一片一片地把 A、B 的小块搬进 SMEM，在片上反复使用。

记号（本节）
符号含义单位
$T$C 的分块边长（一个线程块负责 $T\times T$ 个输出）元素
$T_k$沿 $k$ 方向每次搬入的宽度元素
$n_\text{stage}$SMEM 里同时放几片（边算边搬下一片）—

  1. 每一步搬入 A 的 $T\times T_k$ 和 B 的 $T_k\times T$，共 $2TT_k$ 个元素（BF16 每个 2 字节），做 $T^2T_k$ 次乘加：

    $$F_\text{step}=2T^2T_k,\quad M_\text{step}=4TT_k$$

  2. 单步的算术强度只取决于 $T$，和矩阵多大无关：

    $$I_\text{tile}=\frac{F_\text{step}}{M_\text{step}}=\frac{T}{2}\ \text{FLOP/B}$$

  3. $T$ 越大强度越高，但片上放不下：SMEM 要放 $n_\text{stage}\cdot 4TT_k$ 字节，FP32 累加器要 $4T^2$ 字节，而一个 SM 的寄存器只有 256 KB：

    $$T=256\ \Rightarrow\ 4T^2=256\text{ KB}$$

算术强度与 roofline

算术强度 $I$：一个算子做的浮点运算数除以它读写 HBM 的字节数。roofline 用它判断算子受算力限制还是受带宽限制。

记号
符号含义单位
$\pi$峰值算力FLOP/s
$\beta$HBM 带宽B/s
$F$算子的浮点运算数FLOP
$M$算子读写 HBM 的字节数B
$t,\ k,\ n$线性层 $Y=XW$ 中 $X\in\mathbb{R}^{t\times k}$，$W\in\mathbb{R}^{k\times n}$；$t$ 是这次参与计算的 token 数—

  1. 算和搬可以重叠，耗时至少是两者中较大的一个：

    $$t_\text{op}\ge\max\!\left(\frac{F}{\pi},\ \frac{M}{\beta}\right)$$

  2. 记 $I=F/M$，能达到的性能是一条折线：

    $$P=\frac{F}{t_\text{op}}=\min(\pi,\ \beta I)$$

  3. 折点叫拐点。H100 BF16：$989/3.35\approx 295$；B200 BF16：$2250/8\approx 281$ FLOP/B。

    $$I^*=\pi/\beta$$

  4. 线性层：$F=2tkn$，BF16 下至少读 $X$、$W$ 并写 $Y$：

    $$I=\frac{2tkn}{2(tk+kn+tn)}=\frac{tkn}{tk+kn+tn}$$

  5. 方阵权重 $k=n=h$ 时：

    $$I=\frac{th}{2t+h}\ \approx\ \begin{cases}t, & t\ll h\\ h/2, & t\gg h\end{cases}$$

训练时 $t=b\cdot s$ 有几千上万，线性层落在算力区；解码时 $t$ 就是并发请求数，batch 为 1 时 $I\approx 1$，只能用到峰值的千分之几。逐元素算子（残差加、激活函数、RMSNorm、softmax）每个元素只做几次运算却要读写一遍，$I\lesssim 1$，永远受带宽限制。对这类算子，优化手段是融合（几个算子一次读写完成），减少 $M$ 而不是 $F$。标准 attention 把 $s\times s$ 的分数矩阵写回 HBM 再读出来做 softmax，正是这个问题，见 FlashAttention。

易错

NVIDIA 规格页上 Tensor Core 的数字常常是 2:4 结构化稀疏下的值，稠密峰值是它的一半。训练几乎都是稠密计算，算 MFU 要用稠密值（H100 BF16 是 989，不是 1979）。

一步训练的 FLOPs

记号（本页通用）
符号含义典型值
$N$参数量$8\times 10^9$
$D$训练 token 总数$15\times 10^{12}$
$L,\ h,\ a$层数、隐藏维、注意力头数32, 4096, 32
$s,\ b$序列长度、micro-batch 的序列数8192, 1
$V$词表大小128256
$G$GPU 数—

  1. 线性层 $Y=XW$（$X\in\mathbb{R}^{t\times k}$，$W\in\mathbb{R}^{k\times n}$）前向：每个输出元素做 $k$ 次乘加：

    $$F_\text{fwd}=2tkn$$

  2. 反向要算两个矩阵乘：传给上一层的 $\partial X$ 和权重梯度 $\partial W$，各与前向一样大：

    $$F_\text{bwd}=\underbrace{2tkn}_{\partial X=\partial Y W^\top}+\underbrace{2tkn}_{\partial W=X^\top\partial Y}$$

  3. $W$ 有 $kn$ 个参数，处理 $t$ 个 token：每个参数每个 token 前向 2、反向 4，共 6 次运算。对所有权重求和：

    $$C_\text{dense}\approx 6ND$$

  4. attention 核心 $QK^\top$ 和 $PV$ 没有参数，每层每 token 前向 $2sh+2sh$，训练乘 3：

    $$C_\text{attn}=12\,Lhs\ \text{每 token}$$

  5. GPT 式一层的权重是 $4h^2$（Q、K、V、O）加 $8h^2$（MLP，中间维 $4h$），所以每 token 每层：

    $$\underbrace{72h^2}_{6\times 12h^2}+12sh,\qquad \frac{\text{attention}}{\text{线性层}}=\frac{s}{6h}$$
$$C_\text{train}\approx(6N+12Lhs)\,D$$

$s\ll 6h$ 时 attention 项可以忽略，用 $C_\text{train}\approx 6ND$ 估算就够了。

例：Llama 3 405B 训练 15.6T token，$6ND=6\times 4.05\times 10^{11}\times 1.56\times 10^{13}\approx 3.8\times 10^{25}$ FLOPs，和论文报告的数一致。$12Lhs$ 是 PaLM 附录 B 的记法，按完整的 $s\times s$ 计；因果掩码下 FlashAttention 跳过上三角，实际只算一半，有的论文按 $6Lhs$ 记，比较 MFU 时要看清用的是哪种。

MFU 与 HFU

MFU（model FLOPs utilization）：实际训练吞吐对应的模型 FLOPs，占硬件峰值的比例。分子只算模型本身必需的 $6N+12Lhs$，不管实现里多做了什么。

$$\text{MFU}=\frac{r\,(6N+12Lhs)}{\pi}$$

其中 $r$ 是每卡每秒处理的 token 数。

HFU（hardware FLOPs utilization）把实际执行的重计算也算进分子。全量重计算会多做一次前向（$2N+4Lhs$ 每 token），HFU 因此比 MFU 高；MFU 不受实现方式影响，适合拿来比较不同系统。两个数都来自 PaLM（2022）：540B 模型在 6144 块 TPU v4 上 MFU 46.2%，HFU 57.8%。Llama 3 405B 在 8k–16k 块 H100 上报告 BF16 MFU 38%–43%。

  1. $G$ 块卡、MFU 为 $u$，每秒完成的模型 FLOPs：

    $$G\,\pi\,u$$

  2. 总量 $6ND$ 除以速率就是训练时间：

    $$T_\text{train}=\frac{6ND}{G\,\pi\,u}$$

MFU 到不了 100% 的原因：逐元素算子受带宽限制（上一节），通信没被计算完全盖住（集合通信），流水线有气泡（流水线并行），以及 kernel 启动、数据加载、checkpoint 保存的开销。

显存账

训练显存 = 模型状态（参数、梯度、优化器状态）+ 激活 + 临时缓冲与碎片。模型状态只和参数量有关，激活和 $b\cdot s$ 成正比。

后三项合称优化器状态，ZeRO 论文记作 $K=12$。为什么要留一份 FP32 主权重见混合精度，Adam 的两个矩见优化器。7B 模型的模型状态就要 $16\times 7\times 10^9=112$ GB，一张 80 GB 的卡放不下，这是 ZeRO / FSDP 把它们切到多张卡上的原因。

激活：每层 $sbh(34+5as/h)$ 字节

反向要用前向的中间结果，它们从前向一直留到对应层的反向结束。下面按 Korthikanti et al.（2022）的方法，逐个数一层 GPT 式 Transformer 存了什么：激活 16 位（2 字节），dropout 掩码 1 字节，MLP 中间维 $4h$。

  1. attention 的线性部分：QKV 投影的输入 $2sbh$，算 $QK^\top$ 要的 Q、K 共 $4sbh$，V 为 $2sbh$，输出投影的输入 $2sbh$，输出 dropout 掩码 $sbh$：

    $$11\,sbh$$

  2. attention 核心：softmax 输出 $2as^2b$，它的 dropout 掩码 $as^2b$，dropout 后的概率 $2as^2b$：

    $$5\,as^2b$$

  3. MLP：第一层输入 $2sbh$，GeLU 输入 $8sbh$，第二层输入 $8sbh$，dropout 掩码 $sbh$：

    $$19\,sbh$$

  4. 两个 LayerNorm 各存输入 $2sbh$：

    $$4\,sbh$$

  5. 相加，并提出 $sbh$：

    $$A_\text{layer}=34\,sbh+5\,as^2b=sbh\left(34+\frac{5as}{h}\right)\ \text{字节}$$

  6. 全模型再加输出层：交叉熵要存 FP32 的 logits：

    $$A=L\cdot A_\text{layer}+4sbV$$

$5as/h$ 这一项随 $s$ 线性增长。$h=4096$、$a=32$、$s=4096$、$b=1$ 时，每层 $34sbh=0.57$ GB，$5as^2b=2.68$ GB，32 层共 104 GB。FlashAttention 不存 $s\times s$ 的概率矩阵（只存输出和每行的 logsumexp，反向时重算），整项消失，剩 18 GB，见 FlashAttention 的反向。Llama 类模型没有 dropout、MLP 用 SwiGLU，系数会变，量级不变。

临时缓冲与碎片

除了上面两类，还有通信缓冲（DDP 的梯度桶、FSDP 预取的参数）、cuBLAS / NCCL 的工作区，以及 PyTorch 缓存分配器的碎片：张量大小不断变化时，空闲块切不出一整块大空间，nvidia-smi 显示占满但实际在用的远少于此。设置 PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True 可以缓解。估算时通常预留 10%–20%。

激活重计算

激活重计算（activation checkpointing）：前向只存少数几个检查点，反向到某一段时从最近的检查点把这一段前向再跑一遍，拿回中间激活。用算力换显存。

记号
符号含义单位
$A$一层前向产生的全部激活字节
$c$一个检查点（一层的输入，$2sbh$）字节
$k$每隔几层存一个检查点层

  1. 前向只存 $L/k$ 个检查点；反向处理一段时，把这一段的 $k$ 层重算出来：

    $$\text{峰值}\approx\frac{L}{k}\,c+k\,A$$

  2. 对 $k$ 求最小：

    $$k^*=\sqrt{Lc/A},\qquad \text{峰值}^*=2\sqrt{L\,c\,A}$$

  3. 如果每个节点存的就是它的全部激活（$c=A$，Chen et al. 2016 的设定），$k^*=\sqrt{L}$：

    $$LA\ \rightarrow\ 2\sqrt{L}\,A$$

    Transformer 一层的输入只有 $2sbh$，内部激活是它的十几倍以上，最优 $k$ 接近 1，所以框架默认按层存输入。

  4. 代价：反向前多跑一遍前向，前向占一步的三分之一：

    $$6N\ \rightarrow\ 8N\ \text{每 token},\quad +33\%$$

选择性重计算（Korthikanti et al. 2022）只重算 attention 核心：$5as^2b$ 那一项占激活的大头，重算它只要 $4Lhs$ 次运算（前向的 attention 核心），远少于整层。FlashAttention 的反向本来就重算概率矩阵，所以用了 FlashAttention 就相当于已经做了选择性重计算。

梯度累积与全局 batch

梯度累积：一张卡一次只跑 $b$ 条序列（micro-batch），连跑 $m$ 次只累加梯度、不更新参数，第 $m$ 次之后再做一次优化器更新。等效 batch 变大，激活显存只按 $b$ 算。

  1. 再乘上数据并行的卡数 $p$，一次参数更新看到的序列数：

    $$B_\text{global}=b\cdot m\cdot p,\qquad \text{token 数}=B_\text{global}\cdot s$$

  2. 想要的梯度是全局所有 token 损失的平均。设第 $j$ 个 micro-batch 有 $T_j$ 个有效 token，$\ell_i$ 是第 $i$ 个 token 的损失：

    $$g=\frac{1}{\sum_j T_j}\sum_j\sum_{i\in j}\nabla\ell_i$$

  3. 常见写法是每个 micro-batch 先在自己内部取平均，再除以 $m$。每个 token 的权重变成：

    $$w_i=\frac{1}{m\,T_j}\ \neq\ \frac{1}{\sum_j T_j}\quad(\text{除非各 }T_j\text{ 相等})$$

  4. 修正：每个 micro-batch 只求和，最后除以全局有效 token 数（多卡时这个数也要 all-reduce）。

前 $m-1$ 个 micro-batch 不需要同步梯度，DDP 用 no_sync() 跳过这几次 all-reduce，只在最后一次通信，见 DDP。流水线并行里 micro-batch 还决定气泡大小，见 流水线并行。

自测

13B 模型用 BF16 + Adam 全参训练，不算激活，至少要多少显存？

$16\times 13\times 10^9=208$ GB。至少要用 ZeRO / FSDP 把模型状态切到 3 张以上 80 GB 的卡上，还没算激活。

batch 为 1 的解码，为什么跑不满 Tensor Core？

线性层的 $t=1$，算术强度 $I=th/(2t+h)\approx 1$ FLOP/B，远低于 H100 BF16 的拐点 295。时间全花在把权重从 HBM 读出来上，能用到的算力约 $3.35$ TFLOPS。

为什么训练每参数每 token 是 6 次运算，而不是 2 次？

前向一次矩阵乘是 2（一乘一加）。反向要算对输入的梯度 $\partial Y W^\top$ 和对权重的梯度 $X^\top\partial Y$ 两个同样大的矩阵乘，共 4。

$h=8192$ 的模型，序列多长时 attention 核心的 FLOPs 和全部线性层一样多？

$s=6h=49152$。比它短，$6ND$ 是不错的近似；比它长，attention 项占大头。

同一套训练，打开全量重计算后吞吐降了 20%。MFU 和 HFU 怎么变？

MFU 跟吞吐成正比，降 20%。HFU 的分子多了一次前向（$\times 8/6$），乘上 0.8 后约为原来的 1.07 倍，略有上升。

FlashAttention 让激活公式 $sbh(34+5as/h)$ 里的哪一项消失？为什么？

$5as^2b$，即 softmax 输出、dropout 掩码和 dropout 后的概率。FlashAttention 不把 $s\times s$ 矩阵写回 HBM，只存输出和每行的 logsumexp，反向时分块重算概率。

梯度累积 $m$ 步，什么时候和一次跑 $m$ 倍大的 batch 不等价？

各 micro-batch 的有效 token 数不同，而损失又在每个 micro-batch 内先取平均时：短的 micro-batch 里每个 token 权重更大。改成求和后除以全局 token 数即可等价。
