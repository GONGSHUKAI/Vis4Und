数值精度与混合精度

每个张量用几位存、几位算，决定了显存占用、通信量和 Tensor Core 吞吐。这一页从浮点数的位布局讲起，到 BF16 混合精度为什么还要 FP32 主权重、FP16 为什么要 loss scaling、FP8 的缩放因子怎么定，再到 Blackwell 上的 MXFP8 / NVFP4 块缩放格式和 4 位预训练的配方。

读完能回答

  • BF16 和 FP16 都是 16 位，为什么大模型训练用 BF16？
  • 计算用 BF16，为什么主权重和 Adam 状态还要 FP32？
  • FP8 的缩放因子怎么算，按整个张量、按 token 还是按块？
  • MXFP4 和 NVFP4 差在哪，4 位预训练靠什么稳住？

浮点数的构成

浮点数用符号位 $s$、$E$ 位指数域 $e$、$M$ 位尾数域 $m$ 表示一个实数 $x=(-1)^s\cdot 2^{e-b}\cdot(1.m)_2$。指数决定量级（范围），尾数决定同一量级里分得多细（精度）。

记号
符号含义取值
$s$符号位，0 正 1 负1 位
$e$指数域，按无符号整数读$E$ 位，$0\ldots 2^E-1$
$m$尾数域（小数点后的位）$M$ 位，$0\ldots 2^M-1$
$b$指数偏置，通常 $2^{E-1}-1$整数
$\mathrm{fl}(x)$把实数 $x$ 舍入到最近的可表示数—
$\mathrm{ulp}(x)$$x$ 附近相邻两个可表示数的间距与 $x$ 同单位
$\varepsilon$机器 ε：1 到下一个可表示数的距离$2^{-M}$

  1. 正规数（$1\le e$，且 $e$ 不是保留给 ∞/NaN 的全 1）：尾数前有一个不存储的隐含 1。

    $$x=(-1)^s\,2^{e-b}\Big(1+\frac{m}{2^M}\Big)$$

  2. 固定 $e$，$m$ 的 $2^M$ 个取值在区间 $[2^k,2^{k+1})$（$k=e-b$，叫一个 binade）里等距排开：

    $$\mathrm{ulp}=2^{k-M}$$

  3. 间距和 $|x|$ 同比例增长，所以相对误差有统一上界；就近舍入最多差半个间距：

    $$\frac{|\mathrm{fl}(x)-x|}{|x|}\le\frac{2^{k-M}/2}{2^k}=2^{-M-1}=\frac{\varepsilon}{2}$$

  4. 最小正规数是 $e=1,m=0$。IEEE 格式把 $e$ 全 1 留给 ∞ 和 NaN，最大有限数取 $e=2^E-2$、$m$ 全 1：

    $$x^{\text{norm}}_{\min}=2^{1-b},\qquad x_{\max}=2^{\,2^E-2-b}\,(2-2^{-M})$$

  5. $e=0$ 时去掉隐含的 1，叫次正规数（subnormal），用和最低 binade 相同的间距把 $[0,2^{1-b})$ 填满：

    $$x=(-1)^s\,2^{1-b}\,\frac{m}{2^M},\qquad x^{\text{sub}}_{\min}=2^{1-b-M}$$

  6. 动态范围按能覆盖多少个 binade 算。FP16 约 40 个，FP8 E4M3 约 17.8 个，FP4 E2M1 只有 3.6 个：

    $$R=\log_2\frac{x_{\max}}{x^{\text{sub}}_{\min}}$$
舍入

默认的舍入是就近舍入、恰好在中点时取尾数末位为 0 的一边（round-to-nearest-even，RNE）：中点一半向上一半向下，长期累积不偏。另一种是按距离抽签的随机舍入。

易错

FP8 E4M3 和 FP6 / FP4 不是 IEEE 格式。E4M3 不留 ∞，只有 S.1111.111 是 NaN，所以指数全 1 也能表示普通数，最大值是 $1.75\times 2^8=448$；FP6、FP4 连 NaN 都没有。套用上面第 4 步的 IEEE 公式会算错它们的最大值。

BF16 与 FP16：BF16 就是 FP32 截掉低 16 位尾数，指数位一样，范围也和 FP32 一样，FP32→BF16 的转换只是对低 16 位做一次舍入；代价是只剩 7 位尾数。FP16 多 3 位尾数，但 5 位指数只覆盖 $[2^{-24},\,65504]$，很多梯度比 $2^{-24}$ 还小，需要 loss scaling。A100 起 Tensor Core 支持 BF16 后，大模型训练基本都换成了 BF16。

TF32

TF32 不是存储格式。张量照旧按 FP32 存，Tensor Core 做矩阵乘时把输入的尾数截到 10 位、按 FP32 累加（A100 起）。PyTorch 1.12 起矩阵乘默认不用 TF32，torch.set_float32_matmul_precision("high") 打开。

混合精度训练

混合精度训练：矩阵乘的输入用低精度（BF16 / FP16 / FP8），而需要长期累加的量——主权重、优化器状态、GEMM 内部的累加、跨卡归约——用 FP32。

张量常见精度原因
参数的计算副本BF16喂给 GEMM
主权重FP32小更新不被吞掉，见下面的推导
Adam 的 $m, v$FP32同上；压缩做法见优化器状态的显存

按这张表，每个参数占 2（BF16 参数）+ 2（BF16 梯度）+ 12（FP32 主权重、$m$、$v$）= 16 字节，显存账见显存与算力。

更新为什么会被吞掉

  1. 一步更新：$\Delta=-\eta\,u$，$u$ 是优化器给出的更新方向，结果要舍入回权重的存储格式：

    $$w\leftarrow\mathrm{fl}(w+\Delta)$$

  2. $|\Delta|$ 小于半个间距时，就近舍入回到 $w$ 本身：

    $$|\Delta|\lt\tfrac12\,\mathrm{ulp}(w)\ \Rightarrow\ \mathrm{fl}(w+\Delta)=w$$

  3. BF16 里 $w\in[1,2)$ 时 $\mathrm{ulp}=2^{-7}$，阈值是 $2^{-8}\approx3.9\times10^{-3}$。Adam 的 $|u|$ 约为 1，学习率 $3\times10^{-4}$ 时 $|\Delta|\approx3\times10^{-4}$，远低于阈值，整步更新丢失。

  4. FP32 在同一处的阈值是 $2^{-24}\approx6\times10^{-8}$，同样的更新能加上去。所以计算用 BF16，权重的「账本」留在 FP32。

  5. 点积同理：顺序累加 $K$ 项，部分和 $S$ 越来越大，$\mathrm{ulp}(S)$ 跟着变大，加数小于 $\mathrm{ulp}(S)/2$ 后就被吞掉，所以 GEMM 用 FP32 累加器。

    $$S_k=\mathrm{fl}(S_{k-1}+x_k),\qquad x_k\lt\tfrac12\,\mathrm{ulp}(S_{k-1})\Rightarrow S_k=S_{k-1}$$

PyTorch 里：torch.autocast("cuda", dtype=torch.bfloat16) 把 matmul、卷积换成 BF16，把 softmax、log_softmax、layer_norm、损失函数等留在 FP32；参数本身仍是 FP32，就是主权重。分布式框架里参数通常以 BF16 存、FP32 副本放在优化器里；FSDP 用 MixedPrecision(param_dtype, reduce_dtype) 分别设计算和归约的精度，见 FSDP。

FP16 的 loss scaling

Loss scaling：反向传播前把 loss 乘一个大数 $S$，让所有梯度整体移出 FP16 的下溢区；优化器更新前再除回去。

  1. 反向传播是线性的，loss 乘 $S$，每个梯度都乘 $S$，在 $\log_2$ 轴上整体右移 $\log_2 S$：

    $$\nabla_\theta(S\,\mathcal L)=S\,\nabla_\theta\mathcal L$$

  2. FP16 最小的非零数是 $2^{-24}$，比它的一半还小的值舍入成 0。乘 $S$ 后下溢条件变成：

    $$|g|\lt 2^{-25}/S$$

  3. 上界：任何一个元素 $S|g|$ 超过 65504 就得到 inf，整步梯度作废。

    $$S\cdot\max|g|\le 65504$$

  4. 更新前在 FP32 里除回；梯度裁剪要在除回之后做，否则阈值被放大了 $S$ 倍：

    $$g=\tfrac1S\,\nabla_\theta(S\,\mathcal L)$$

  5. 动态调整：某步出现 inf / NaN 就跳过这步并 $S\leftarrow S/2$；连续 $N$ 步正常就 $S\leftarrow 2S$。PyTorch GradScaler 默认 $S_0=2^{16}$、$N=2000$。

BF16 不需要

BF16 的最小正规数是 $2^{-126}$，和 FP32 一样，梯度不会下溢，所以 BF16 训练不做 loss scaling，也就没有被跳过的步。

FP8 训练与缩放

缩放因子：FP8 只覆盖 18 到 32 个 binade，张量要先除以一个 FP32 的缩放因子 $s$，把数值挪进格式范围再转换：$q=\mathrm{fl}_8(x/s)$，使用时还原成 $\hat x=s\,q$。

记号
符号含义形状
$X$线性层的输入激活（$T$ 个 token）$T\times d_\text{in}$
$W$权重$d_\text{in}\times d_\text{out}$
$Y=XW$输出$T\times d_\text{out}$
$\delta X,\ \delta W,\ \delta Y$loss 对 $X, W, Y$ 的梯度同对应张量
$Q_X,\ Q_W$FP8 编码后的张量同 $X, W$
$s_X,\ s_W$缩放因子（FP32）标量，或每组一个
$\operatorname{amax}$一组元素的最大绝对值标量
$q_{\max}$格式最大值：E4M3 为 448，E5M2 为 57344标量

一个线性层每步有三个 GEMM：

$$\underbrace{Y=XW}_{\text{Fprop}},\qquad \underbrace{\delta X=\delta Y\,W^\top}_{\text{Dgrad}},\qquad \underbrace{\delta W=X^\top\delta Y}_{\text{Wgrad}}$$

经典配方（Micikevicius et al. 2022，Transformer Engine 早期默认）：前向的 $X, W$ 用 E4M3（要精度），反向的 $\delta Y$ 用 E5M2（梯度跨度大，要范围）。

  1. 每组取 $s=\operatorname{amax}/q_{\max}$，组内最大值正好映到格式的最大值，不溢出：

    $$q=\mathrm{fl}_8(x/s),\qquad |x/s|\le q_{\max}$$

  2. 整张量共用一个 $s$（per-tensor）时，GEMM 结果只需最后乘一次：

    $$Y=s_X\,s_W\,(Q_XQ_W)$$

  3. 沿收缩维每 $B$ 个元素一组、每组一个缩放时，求和要按组拆开，$g$ 是收缩维上的组号：

    $$Y_{ij}=\sum_{g} s^X_{i,g}\,s^W_{g,j}\sum_{k\in g}q^X_{ik}\,q^W_{kj}$$

  4. 内层和由 Tensor Core 做 FP8 乘加；外层乘上两个缩放，在 FP32 里累加。DeepSeek-V3 报告 H800 上 FP8 GEMM 的累加器只保留约 14 位，于是每 $N_C=128$ 个元素把部分和提升到 CUDA core 的 FP32 寄存器——提升点和第 3 步的组边界重合，提升时顺便乘缩放。

缩放因子从哪来

  • 延迟缩放（delayed scaling）：用前面若干步记录的 amax 历史定这一步的 $s$，转换不必先扫一遍张量，能和产生它的算子融合。amax 突然变大（loss spike、数据分布变化）时，按历史算的 $s$ 偏小，这一步的大值饱和到 $q_{\max}$。
  • 当前缩放（current scaling）：先对当前张量求 amax 再转换，多一次归约，但不受历史拖累。
  • 块缩放：每块的 amax 在块内求，天然是「当前」的，还能隔离离群值。

DeepSeek-V3（671B MoE，2024.12）的 FP8 配方：三个 GEMM 的输入全部用 E4M3——1×128 / 128×128 的细粒度缩放让每组只需覆盖组内范围，不再需要 E5M2 的范围，换来多 1 位尾数；激活按 1×128（每 token 每 128 通道）、权重按 128×128 块缩放；每 128 个元素提升到 FP32 累加；embedding、输出头、MoE gating、归一化和 attention 保持 BF16 / FP32；主权重和用于更新的梯度用 FP32，AdamW 的两个矩用 BF16。FP8 的 attention 见 FlashAttention-3。

块缩放格式：MX 与 NVFP4

微缩放（microscaling，MX）：每 $k$ 个相邻元素共用一个 8 位缩放因子，Tensor Core 在乘加时直接按块解码，不需要软件把 GEMM 拆成组。OCP 在 2023 年发布 MX 规范 v1.0；Blackwell 的 Tensor Core 原生支持 MX 格式和 NVIDIA 自己的 NVFP4。

MX 的缩放

  1. E8M0 只能表示 2 的幂，块内每个值写成 $x_i\approx2^{X}p_i$，$X$ 是整数，$p_i$ 是元素格式里的数。

  2. OCP 规范取 $X$ 为 amax 的指数减去元素格式最大值的指数 $e^\text{elem}_{\max}$（E2M1 为 2，E4M3 为 8），于是 $\operatorname{amax}/2^X\in[4,8)$（对 E2M1），超过 6 的部分截到 6：

    $$X=\lfloor\log_2\operatorname{amax}\rfloor-e^\text{elem}_{\max}$$

  3. Mishra et al.（2025）发现这个向下取整会让 MXFP8 预训练发散，改成向上取整，不再截断，代价是块内最大值可能只用到格式一半的范围：

    $$X=\Big\lceil\log_2\frac{\operatorname{amax}}{q_{\max}}\Big\rceil$$

NVFP4 的两级缩放

  1. 先用整个张量定一个 FP32 缩放，让所有块缩放都落进 E4M3 的范围（$6$ 是 E2M1 最大值，$448$ 是 E4M3 最大值）：

    $$s_g=\frac{\operatorname{amax}(\text{tensor})}{6\times448}$$

  2. 每 16 个元素一个块缩放，舍入到 E4M3 存储，可以取 1.25、1.75 这类非 2 的幂：

    $$s_b=\mathrm{fl}_\text{E4M3}\Big(\frac{\operatorname{amax}(\text{block})}{6\,s_g}\Big)$$

  3. 元素舍入到 E2M1，解码时乘回两级缩放：

    $$q_i=\mathrm{fl}_\text{E2M1}\Big(\frac{x_i}{s_b\,s_g}\Big),\qquad \hat x_i=q_i\,s_b\,s_g$$

  4. 块更小（16 对 32）、缩放更细（E4M3 对 2 的幂），每元素多 0.25 位：$4+8/16=4.5$。

4 位预训练的配方（截至 2026-11）

NVIDIA 的 NVFP4 预训练（arXiv:2509.25149，2025.09）在 12B 的 Mamba-Transformer 混合模型上训了 10T token，loss 和下游精度贴近 FP8 基线（MMLU-Pro 62.58% 对 62.62%）。配方有四部分，消融显示缺一不可：

  • 少数线性层（集中在网络末端的几个 block）保持 BF16；
  • 权重用 16×16 的二维块缩放，这样前向用的 $W$ 和反向用的 $W^\top$ 量化结果一致；
  • Wgrad 的两个输入先做 16×16 的随机 Hadamard 变换（RHT），把块内离群值摊开；
  • 梯度用随机舍入，权重和激活用 RNE。

Transformer Engine 的 NVFP4 recipe 实现了这套组合（权重二维缩放、Wgrad 的 RHT、梯度随机舍入）。NVIDIA 的 Nemotron 3 Super 和 Ultra 用 NVFP4 预训练。MXFP4 方面，Tseng et al.（AISTATS 2025）用 RHT 加随机舍入，把反向传播的大部分 GEMM 放进 MXFP4。

  1. $H$ 是 $16\times16$ 的归一化 Hadamard 矩阵乘一个随机 ±1 对角阵，元素都是 $\pm\frac14$，并且正交：

    $$H^\top H=I$$

  2. Wgrad 沿 token 维收缩。$H_T$ 是沿 token 维每 16 个一块的块对角矩阵，插进中间不改变结果：

    $$\delta W=X^\top\delta Y=X^\top H_T^\top H_T\,\delta Y=(H_TX)^\top(H_T\,\delta Y)$$

  3. 量化的是 $H_TX$ 和 $H_T\delta Y$：每个输出元素是 16 个输入的 $\pm\frac14$ 加权和，一个离群值被均摊到 16 个位置上，块内 amax 与 RMS 之比变小，小元素不再被压成 0。

随机舍入

随机舍入（stochastic rounding，SR）：$x$ 落在相邻可表示数 $q_-\lt x\lt q_+$ 之间时，离哪边近就以更大概率取哪边。

  1. 按距离定概率：

    $$\mathrm{SR}(x)=\begin{cases}q_+ & \text{概率 } p=\dfrac{x-q_-}{q_+-q_-}\\[4pt] q_- & \text{概率 } 1-p\end{cases}$$

  2. 期望等于原值，无偏：

    $$\mathbb E[\mathrm{SR}(x)]=q_-+p\,(q_+-q_-)=x$$

  3. 方差不超过 $\mathrm{ulp}^2/4$；单次误差比 RNE 大，RNE 的好处是误差小、坏处是有偏：

    $$\operatorname{Var}=p(1-p)(q_+-q_-)^2\le\tfrac14\,\mathrm{ulp}^2$$

  4. 连加 $n$ 个比半个 ulp 还小的 $\Delta$：RNE 每步都舍回原值，误差是 $n\Delta$；SR 的误差是 $n$ 个独立零均值项之和，标准差只按 $\sqrt n$ 增长。

随机舍入适合会被反复累加的量：低位训练里的梯度（NVFP4、MXFP4 配方），以及不留 FP32 主权重、直接用低精度存权重时的更新。前向的权重和激活只用一次，用误差更小的 RNE。

自测

BF16 和 FP16 都是 16 位，为什么大模型训练用 BF16？

BF16 有 8 位指数，范围和 FP32 一样（最小正规数 $2^{-126}$），梯度不下溢、激活不溢出，不需要 loss scaling，也没有被跳过的步。FP16 多 3 位尾数，但范围只有 $2^{-24}$ 到 65504。

学习率 $10^{-4}$、Adam 更新幅度约 1，一个值为 0.8 的权重存在 BF16 里会怎样？

$0.8\in[0.5,1)$，BF16 间距是 $2^{-8}$，被吞掉的阈值是 $2^{-9}\approx1.95\times10^{-3}$。$|\Delta|=10^{-4}$ 远小于阈值，每一步都舍回 0.8，权重不动。需要 FP32 主权重，或者对更新用随机舍入。

没有溢出时，loss scaling 为什么不改变梯度？

反向传播对 loss 是线性的，乘 $S$ 再除 $S$ 抵消；$S$ 取 2 的幂时乘除都是精确的，只改变中间值落在哪个 binade，从而避免下溢。改变的只是舍入误差，不是梯度本身。

经典 FP8 配方让梯度用 E5M2，为什么 DeepSeek-V3 能全部用 E4M3？

按张量缩放时，一个缩放要覆盖整张梯度的跨度，需要 E5M2 的约 32 个 binade。1×128 / 128×128 的块缩放让每组只需覆盖组内的跨度，E4M3 的约 18 个 binade 就够了，还多 1 位尾数。

延迟缩放在什么情况下出问题？

amax 突然变大时（loss spike、数据分布变化），按历史 amax 算出的 $s$ 偏小，$x/s$ 超出 $q_{\max}$，这一步的大值饱和到 448 或 57344。当前缩放和块缩放用的是当下的 amax，没有这个滞后。

MXFP4 和 NVFP4 的每元素位数各是多少，差在哪？

MXFP4：32 个 E2M1 共用一个 E8M0 缩放，$4+8/32=4.25$ 位。NVFP4：16 个 E2M1 共用一个 E4M3 缩放，外加整张量一个 FP32 缩放，$4+8/16=4.5$ 位。NVFP4 的块更小、缩放可以不是 2 的幂，网格更贴合每块的范围，误差更小。

4 位训练为什么只对梯度用随机舍入？

随机舍入无偏但方差更大。梯度会跨步、跨 micro-batch 累加进权重，系统性偏差会一直积累，所以要无偏；前向的权重和激活每次只用一次，RNE 的单次误差更小。

DeepSeek-V3 每 128 个元素提升到 FP32 累加，和 1×128 的分组缩放是什么关系？

缩放沿收缩维每 128 个元素一组，每组的部分和必须先乘该组的 $s^X s^W$ 才能和别的组相加。把提升点放在组边界上，一次操作同时完成反缩放和高精度累加，也绕开了 Tensor Core FP8 累加器只有约 14 位的限制。
