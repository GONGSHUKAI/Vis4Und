并行策略

一张卡放不下或算不完时，可以沿五个方向把训练切开：batch（数据并行，以及再切模型状态的 ZeRO / FSDP）、每层的权重矩阵（张量并行 TP、序列并行 SP）、层的深度（流水线并行 PP）、序列（上下文并行 CP）、MoE 的专家（专家并行 EP / ETP）。这一页按这个顺序推导每种切法省下多少显存、多付多少通信，最后把它们排进同一个集群、估一个配置放不放得下。

总览：每种并行切哪一维

并行策略决定把训练的哪一维分到多张卡上：batch、权重矩阵、层的深度、序列或专家。每种切法省下一部分显存或计算，代价是一种特定的集合通信（各原语的通信量见集合通信）。

数据并行

数据并行（data parallelism, DP）：$N_d$ 张卡各存一份完整模型，各处理不同的样本；反向后把各卡的梯度求平均（all-reduce），每张卡做同样的更新，所以参数始终一致。

记号（本页沿用 ZeRO 论文：参数个数记 $\Psi$）
符号含义形状 / 单位
$N_d$数据并行组的卡数（即这一组的 rank 数 $p$）标量
$B$每卡一个 micro-batch 的样本数标量
$x_{ij}$第 $i$ 张卡上的第 $j$ 个样本—
$\ell(x;\theta)$单个样本的损失标量
$g_i$第 $i$ 张卡的本地梯度同 $\theta$，$\Psi$ 个元素
$\bar g$all-reduce 后的平均梯度同 $\theta$
$\Psi$模型参数个数标量

  1. 全局 batch 有 $N_dB$ 个样本，损失是它们的平均，可以按卡分组：

    $$L(\theta)=\frac{1}{N_dB}\sum_{i=1}^{N_d}\sum_{j=1}^{B}\ell(x_{ij};\theta)=\frac{1}{N_d}\sum_{i=1}^{N_d}\underbrace{\frac1B\sum_{j=1}^{B}\ell(x_{ij};\theta)}_{L_i(\theta)}$$

  2. 求导是线性的，全局梯度就是各卡本地梯度的平均：

    $$\nabla L(\theta)=\frac{1}{N_d}\sum_{i=1}^{N_d}g_i,\qquad g_i=\nabla L_i(\theta)$$

  3. all-reduce 求和再除以 $N_d$，每张卡拿到同一个 $\bar g$。初始参数相同（DDP 构造时从 rank 0 广播），更新规则 $U$ 相同，参数就一直相同：

    $$\theta^{t+1}=\theta^{t}-\eta\,U(\bar g^{\,t})$$

  4. 样本独立同分布、单样本梯度方差为 $\sigma^2$ 时，平均梯度的方差按全局 batch 下降：

    $$\operatorname{Var}[\bar g]=\frac{\sigma^2}{N_dB}$$

所以 DP 只是把全局 batch 放大到 $N_dB$。卡数翻倍而每卡 batch 不变时全局 batch 也翻倍，学习率通常要跟着调（线性缩放规则，Goyal et al. 2017）；超过「临界 batch」后，步数不再按比例减少（McCandlish et al. 2018），这限制了单靠 DP 能用多少卡。每卡放不下想要的 batch 时用梯度累积，见 显存与算力账：梯度累积。

易错

按 token 平均的损失。各卡 token 数不同（变长序列、掩码）时，先卡内按 token 平均、再卡间平均，等于给 token 少的卡加了权。要和单卡大 batch 一致，应该卡内求和、除以全局 token 总数（先 all-reduce 一次 token 计数）。

BatchNorm。它的均值方差只在本卡样本上算，DP 下不等价于大 batch；需要全局统计时用 SyncBatchNorm。LayerNorm / RMSNorm 按样本归一化，不受影响。

DDP：梯度分桶，边反向边通信

DDP（PyTorch DistributedDataParallel）给每个参数挂一个 autograd hook；一个桶里的梯度全部就绪，就在通信流上异步发起这个桶的 all-reduce，和剩下各层的反向计算同时进行。

  • 参数按 model.parameters() 的逆序装桶（近似反向计算的顺序）。桶上限 bucket_cap_mb 默认 25 MiB，第一个桶 1 MiB，好让通信尽早开始；第一次迭代后按实际就绪顺序重建桶。
  • 梯度写在桶的连续缓冲里，一个桶一次 all-reduce，而不是每个参数一次；gradient_as_bucket_view=True 让 .grad 直接指向桶缓冲，省一份拷贝。
  • 某些参数在一步里不参与计算时要开 find_unused_parameters=True，否则那个桶永远等不齐。

  1. 一个 $S$ 字节的桶，用 ring all-reduce 在 $p$ 张卡间同步，按 α-β 模型（见 集合通信：代价模型）用时：

    $$T(S)=\alpha+\frac{2(p-1)}{p}\cdot\frac{S}{\beta}$$

  2. 全部梯度 $S_\text{tot}$ 分成 $n$ 个桶，通信总时长里固定开销随桶数线性增长：

    $$T_\text{comm}=n\alpha+\frac{2(p-1)}{p}\cdot\frac{S_\text{tot}}{\beta}$$

  3. 只有反向结束后通信还没做完的那段 $T_\text{exposed}$ 才拉长一步：

    $$T_\text{step}\approx T_\text{fwd}+T_\text{bwd}+T_\text{exposed}+T_\text{opt}$$

  4. 桶太小，$n\alpha$ 变大；桶太大，最后一桶要等反向几乎做完才发出、而且大，$T_\text{exposed}$ 变大。

梯度累积

前几个 micro-batch 放在 with model.no_sync(): 里，梯度只在本地累加、不发 all-reduce；最后一个 micro-batch 正常反向，一次同步累加好的梯度。

ZeRO：把模型状态切成 $N_d$ 份

ZeRO（Zero Redundancy Optimizer，Rajbhandari et al. 2020）：DP 里每张卡都存一整份参数、梯度和优化器状态，这是冗余的。ZeRO 把它们沿参数维切成 $N_d$ 片，每卡长期只存自己那一片，用到别的片时再通信取回。三个阶段依次多切一样东西。

混合精度 Adam 每个参数占 16 字节：BF16 参数 2、BF16 梯度 2、FP32 主权重与一阶、二阶矩共 $K=12$（来由见 显存与算力账：显存账）。激活不在其中，ZeRO 的数据并行部分也不切激活。

记号
符号含义单位
$\Psi$参数个数个
$N_d$数据并行组的卡数张
$K$每参数优化器状态的字节数（混合精度 Adam 为 12）字节
$M_k$ZeRO-$k$ 下每卡模型状态显存字节

  1. DP：每卡全存。

    $$M_\text{DP}=(2+2+K)\Psi=16\Psi$$

  2. ZeRO-1（$P_{os}$，切优化器状态）：每卡只负责更新 $1/N_d$ 的参数，只需要这部分的 FP32 主权重和矩。

    $$M_1=2\Psi+2\Psi+\frac{K\Psi}{N_d}$$

  3. ZeRO-2（$P_{os+g}$，再切梯度）：一片梯度只在负责更新它的那张卡上需要求和结果，reduce-scatter 之后别的卡就可以丢掉。

    $$M_2=2\Psi+\frac{(2+K)\Psi}{N_d}$$

  4. ZeRO-3（$P_{os+g+p}$，再切参数）：参数平时也只存一片，前向、反向用到某一层时再 all-gather。

    $$M_3=\frac{(2+2+K)\Psi}{N_d}$$

  5. 论文的例子：$\Psi=7.5\text{B}$、$N_d=64$ 时四者依次是 120、31.4、16.6、1.9 GB。

通信量

下面以元素个数计，忽略 $(p-1)/p$ 因子，和论文一致。

  1. DP 的梯度 all-reduce 等于一次 reduce-scatter 加一次 all-gather，各传约 $\Psi$（见 集合通信：恒等式）：

    $$C_\text{DP}=\underbrace{\Psi}_\text{RS}+\underbrace{\Psi}_\text{AG}=2\Psi$$

  2. ZeRO-1/2 把这两步拆开用：reduce-scatter 梯度 → 每卡用自己那片梯度更新自己那片参数 → all-gather 新参数。总量不变：

    $$C_{1}=C_{2}=\Psi+\Psi=2\Psi$$

  3. ZeRO-3 不常驻完整参数：前向 all-gather 一次，反向再 all-gather 一次，梯度 reduce-scatter 一次；更新后不必再 all-gather，下一步前向会取。

    $$C_3=\Psi+\Psi+\Psi=3\Psi=1.5\,C_\text{DP}$$

ZeRO-1/2 白省显存，不加通信；ZeRO-3 把显存降到 $1/N_d$，代价是多 50% 通信，而且前向的 all-gather 挡在计算前面，必须靠预取藏起来（下一节）。

相关

Adam 是逐元素更新，参数怎么切都能就地算；Muon 这类按整块矩阵运算的优化器需要完整的梯度矩阵，和 ZeRO 的扁平切分冲突，做法见 优化器：分布式 Muon。

Megatron-Core 的 distributed optimizer 属于 ZeRO-1 一类：切 FP32 主权重和优化器状态，梯度 reduce-scatter、新参数 all-gather，常和 TP / PP 一起用。

FSDP：逐单元取回，用完即弃

FSDP（Fully Sharded Data Parallel，Zhao et al. 2023）是 PyTorch 里的 ZeRO-3：把模型分成若干单元（通常一个 Transformer block 一个），每个单元的参数平时只存 $1/N_d$；轮到它计算时 all-gather 成完整参数，算完马上释放。

一步的执行顺序

  1. 前向，单元 $k=1\dots L$：all-gather 参数 → 前向 → 释放完整参数（reshard），只留本卡那片。
  2. 反向，单元 $k=L\dots1$：all-gather 参数 → 反向得到完整梯度 → reduce-scatter，每卡留自己那片梯度 → 释放完整参数和完整梯度。
  3. 优化器：每卡只更新本卡那片参数，不需要通信。

预取：单元 $k$ 计算时就发出下一个单元（反向时是 $k-1$）的 all-gather，通信藏在计算后面。同一时刻最多保留两个完整单元（当前 + 预取）；FSDP1 的 limit_all_gathers 就是这个限流，防止 CPU 发指令太快、一次分配太多完整单元。

记号
符号含义单位
$L$单元个数个
$\Psi_u$一个单元的参数个数（$\Psi\approx L\Psi_u$）个
$A_k$单元 $k$ 为反向保存的激活字节

  1. 常驻的是切开的模型状态：

    $$M_\text{shard}=\frac{16\Psi}{N_d}$$

  2. 反向开始时激活最多；此时完整的有当前和预取两个单元的 BF16 参数，加当前单元的完整梯度：

    $$M_\text{peak}\approx\frac{16\Psi}{N_d}+2\cdot2\Psi_u+2\Psi_u+\sum_{k=1}^{L}A_k$$

  3. 单元越大，第二、三项越大；单元越小，集合通信次数 $3L$ 越多，固定开销 $\alpha$ 越难摊薄。整个模型当一个单元时第二项变成 $2\Psi$ 字节，等于退回 ZeRO-2。

reshard_after_forward

  • True（非根单元的默认值）：前向后释放，反向再 all-gather 一次，通信 $3\Psi$。
  • False：完整参数一直留到该单元反向结束，省掉反向那次 all-gather，通信 $2\Psi$，但前向结束时所有单元都是完整的，效果接近 ZeRO-2（FSDP1 里叫 SHARD_GRAD_OP）。根单元默认 False，因为反向一开始就要用它。
  • 整数 $k$（FSDP2）：前向后只切到 $k$ 张卡（例如一个节点的 8 卡），反向的 all-gather 只在节点内做，显存介于两者之间。

FSDP1 与 FSDP2

FSDP1（FullyShardedDataParallel）把一个单元的所有参数拼成一维的 FlatParameter 再均分，一个单元一次通信；但同一单元的参数需要同一 dtype，冻结其中一部分也要额外处理。FSDP2（fully_shard，PyTorch 2.6 起在 torch.distributed.fsdp 下）把每个参数单独沿第 0 维切成 DTensor（Shard(0)），优化器直接作用在 DTensor 上，state dict 也是切开的，和 TP 组成二维并行更直接。

from torch.distributed.fsdp import fully_shard, MixedPrecisionPolicy

mp = MixedPrecisionPolicy(param_dtype=torch.bfloat16, reduce_dtype=torch.float32)
for block in model.layers:
    fully_shard(block, mp_policy=mp)   # 每个 block 一个单元
fully_shard(model, mp_policy=mp)       # 根单元：嵌入、输出层等其余参数
opt = torch.optim.AdamW(model.parameters(), lr=3e-4)   # 在切开的 DTensor 上建优化器
FSDP2 的 16 字节

常见配法是本卡分片存 FP32 参数，param_dtype=bf16 让 all-gather 和计算用 BF16，reduce_dtype=fp32 让梯度按 FP32 归约：每参数 4（FP32 参数）+ 4（FP32 梯度）+ 8（$m,v$）= 16 字节再除以 $N_d$。总数和 ZeRO 的 $2+2+12$ 一样，只是没有常驻的 BF16 副本；代价是 FP32 的 reduce-scatter 字节数翻倍。

易错

梯度累积时如果跳过 reduce-scatter（FSDP2 的 set_requires_gradient_sync(False)），每个单元的完整梯度都要留到最后一个 micro-batch，显存涨到整模型梯度的规模；每个 micro-batch 都 reduce-scatter 则通信乘以累积步数。显存紧时选后者。

HSDP 与 ZeRO++：让通信留在节点内

HSDP（hybrid sharded data parallel）：在每个节点的 $G$ 张卡之间做 FSDP，在 $n$ 个节点之间做复制。同一片参数在每个节点各有一份，节点间只对梯度片做 all-reduce。

记号
符号含义单位
$n$节点数个
$G$每节点卡数，也是 HSDP 的切分组大小张
$M$一份 BF16 完整参数（或梯度）的大小，$M=2\Psi$字节
$V$每个节点每步经网卡发出的数据量字节

  1. 每卡模型状态只切到节点内：

    $$M_\text{HSDP}=\frac{16\Psi}{G}\qquad\text{对比}\qquad M_\text{FSDP}=\frac{16\Psi}{nG}$$

  2. 跨 $n$ 个节点做一次 all-gather 或 reduce-scatter，每个节点至少要发出（收进）其余节点那部分数据，ring 类算法正好达到：

    $$V_\text{AG}=V_\text{RS}=\frac{n-1}{n}M$$

  3. 全局 FSDP 的两次 all-gather 和一次 reduce-scatter 都跨节点：

    $$V_\text{FSDP}=3\cdot\frac{n-1}{n}M$$

  4. HSDP 的 all-gather / reduce-scatter 都在节点内（NVLink）；跨节点只有梯度片的 all-reduce，节点里 $G$ 张卡各管 $M/G$：

    $$V_\text{HSDP}=G\cdot\frac{2(n-1)}{n}\cdot\frac{M}{G}=2\cdot\frac{n-1}{n}M$$

HSDP 的跨节点流量和 DDP 一样，比全局 FSDP 少三分之一；参与每次跨节点集合通信的只有 $n$ 个 rank，延迟更小；而且 FSDP 的跨节点 all-gather 挡在前向关键路径上，HSDP 的跨节点 all-reduce 只出现在反向里、可以和计算重叠。代价是每卡显存只降到 $1/G$。FSDP2 里传一个二维 DeviceMesh (replicate, shard) 就是 HSDP；FSDP1 对应 ShardingStrategy.HYBRID_SHARD。

ZeRO++

ZeRO++（Wang et al., ICLR 2024）在 ZeRO-3 上改了三处通信：qwZ 把前向 all-gather 的权重按块量化成 INT8；hpZ 在每个节点内多存一份按节点切的参数，反向 all-gather 只在节点内做（以显存换通信，和 FSDP2 整数版 reshard_after_forward 同一思路）；qgZ 把梯度量化成 INT4，用分层 all-to-all 代替 reduce-scatter。三者合起来跨节点通信量降为 ZeRO-3 的 1/4，论文在 384 卡上报告最高 2.16 倍吞吐。

Offload：把状态放到 CPU 和 NVMe

Offload：卡少、显存是唯一瓶颈时，把优化器状态（甚至参数）放到 CPU 内存或 NVMe，用 PCIe 带宽和 CPU 算力换显存。

ZeRO-Offload（Ren et al. 2021）的划分：前向、反向在 GPU 上，GPU 只存 16 位参数；FP32 主权重、$m$、$v$ 和梯度放在 CPU，Adam 在 CPU 上跑（DeepSpeed 的 CPU-Adam 用 SIMD 和多线程加速）。论文在单张 V100 上训练了超过 130 亿参数的模型。

  1. 两边各存什么：

    $$M_\text{GPU}=2\Psi+\text{激活},\qquad M_\text{CPU}=\underbrace{12\Psi}_{\text{FP32 主权重}+m+v}+\underbrace{2\Psi}_{\text{梯度}}$$

  2. 每步 PCIe 搬两次：梯度下行、新参数上行。

    $$V_\text{PCIe}=2\Psi+2\Psi=4\Psi\ \text{字节}$$

  3. 梯度下行可以和反向重叠，但 CPU 更新要等梯度到齐，GPU 又要等新参数：

    $$T_\text{step}\approx T_\text{GPU}+T_\text{剩余梯度下行}+T_\text{CPU-Adam}+T_\text{参数上行}$$

  4. 延迟一步更新（DPU）：第 $t$ 步的 CPU 更新和第 $t+1$ 步的 GPU 计算并行，第 $t+1$ 步用的参数还没包含第 $t$ 步的梯度。稳态下：

    $$T_\text{step}\approx\max\big(T_\text{GPU},\ T_\text{梯度下行}+T_\text{CPU-Adam}+T_\text{参数上行}\big)$$

论文只在训练开头若干步之后才打开 DPU，避开早期梯度变化最快的阶段。ZeRO-Infinity（Rajbhandari et al. 2021）在 ZeRO-3 上把参数、梯度、优化器状态都可以放到 CPU 或 NVMe、按需预取，论文报告在 32 台 DGX-2（512 张 V100）上可容纳 32T 参数的模型。PyTorch FSDP2 用 offload_policy=CPUOffloadPolicy() 把分片参数、梯度和优化器计算放到 CPU。

张量并行：Megatron 的切法

张量并行（tensor parallelism，TP）把一层里的权重矩阵切成 $t$ 份放到 $t$ 张卡上，每张卡只算自己那一份，再用集合通信把结果加起来。这 $t$ 张卡叫一个 TP 组，组内每张卡都看到同一批 token。

记号
符号含义形状
$t$TP 组大小（卡数）标量
$b,\ s,\ h,\ a$micro-batch 大小、序列长度、隐藏维、注意力头数标量
$X$一层 MLP 的输入（$bs$ 个 token 摞在一起）$bs\times h$
$A,\ B$MLP 的两个权重$h\times 4h$，$4h\times h$
$A_i,\ B_i$第 $i$ 张卡上的切片：$A$ 的第 $i$ 组列、$B$ 的第 $i$ 组行$h\times\frac{4h}{t}$，$\frac{4h}{t}\times h$
$\sigma$GeLU，逐元素作用—

MLP：先列切，再行切

  1. MLP 是两次矩阵乘中间夹一个逐元素非线性：

    $$Z=\sigma(XA)\,B$$

  2. 把 $A$ 按列切成 $t$ 块。矩阵乘按列可分，$\sigma$ 又逐元素，所以每张卡独立算出自己那几列，不用通信（记 $Y_i=\sigma(XA_i)$）：

    $$\sigma(XA)=\big[\sigma(XA_1),\ \dots,\ \sigma(XA_t)\big]$$

  3. $B$ 按行切，和 $Y$ 的列切正好对上。分块矩阵乘把结果写成 $t$ 个部分和：

    $$Z=\sum_{i=1}^{t} Y_i B_i$$

  4. 每张卡算出 $Y_iB_i$（形状 $bs\times h$），一次 all-reduce 求和，每张卡都拿到完整的 $Z$。

  5. 反过来先把 $A$ 按行切（$X$ 相应按列切）就不行：每张卡只得到部分和 $X_iA_i$，而

    $$\sigma\Big(\sum_i X_iA_i\Big)\neq\sum_i\sigma(X_iA_i)$$

    必须在 $\sigma$ 之前 all-reduce 一个 $bs\times 4h$ 的张量，通信量是列切方案的 4 倍，还多一次同步。

f 和 g：前向、反向各通信一次

列切线性层的输入 $X$ 被 $t$ 张卡同时使用，反向时 $\nabla_X=\sum_i \nabla_{Y_i}A_i^\top$ 是各卡贡献之和，要 all-reduce；行切线性层的输出前向要 all-reduce，反向时 $\nabla_Z$ 每张卡都有完整一份，直接用。Megatron 把这两处写成一对共轭算子：

算子前向反向放在哪
$f$恒等all-reduce列切层前
$g$all-reduce恒等行切层后

注意力：按头切

多头注意力天然可分：第 $i$ 张卡拿 $a/t$ 个头，$W^Q,W^K,W^V$ 按头（列）切，输出投影 $W^O$ 按行切，结构和 MLP 一样，也是 $f$ 进、$g$ 出：

$$O=\sum_{i=1}^{t}\ \mathrm{Attn}\big(XW^Q_i,\ XW^K_i,\ XW^V_i\big)\,W^O_i$$

所以一个 Transformer 层前向 2 次 all-reduce（注意力、MLP 各一次），反向再 2 次，每次 $bsh$ 个元素。GQA 的 KV 头少，KV 头数小于 $t$ 时只能把 KV 头复制到多张卡上。

词表层：按词表切

输入 embedding 和输出层按词表维切，每张卡存 $V/t$ 行。交叉熵不必把 $bs\times V$ 的 logits 收齐：对每个 token，各卡先算本地最大值 $m_i$，all-reduce 取 $m=\max_i m_i$；再算本地 $\sum e^{z_v-m}$，all-reduce 求和；目标词的 logit 只在一张卡上，其余卡填 0 后 all-reduce。每个 token 只传 3 个标量：

$$\ell=\log\sum_{v=1}^{V}e^{z_v}-z_y=m+\log\sum_{i=1}^{t}\ \sum_{v\in\mathcal V_i}e^{z_v-m}\;-\;z_y$$
易错

dropout 的随机种子：在 TP 切开的区域（如各卡自己那几个头的注意力 dropout），各卡要用不同的种子，否则相当于同一个 mask 重复了 $t$ 次；在各卡持有相同张量的区域（行切层之后的 dropout），各卡要用相同的种子，否则各卡的「同一份」激活就不一样了。Megatron 为此单独维护一套模型并行的随机数状态。

TP 的通信量：为什么不出节点

记号
符号含义单位
$\mathcal F$单卡矩阵乘的实际吞吐FLOP/s
$\beta$all-reduce 的总线带宽 busbw（见集合通信）B/s
$T_\text{comp},\ T_\text{comm}$一层前向 + 反向在一张卡上的计算、通信时间s

  1. 一层前向约 $24bsh^2+4bs^2h$ FLOPs（怎么数的），反向是前向的 2 倍，再平分到 $t$ 张卡：

    $$T_\text{comp}=\frac{72\,bsh^2\,(1+\frac{s}{6h})}{t\,\mathcal F}$$

  2. 每层 4 次 all-reduce，每次 $n=2bsh$ 字节（BF16）。ring all-reduce 每卡收发 $2\frac{t-1}{t}n$（推导），按 busbw 的定义：

    $$T_\text{comm}=4\cdot\frac{2(t-1)}{t}\cdot\frac{2bsh}{\beta}=\frac{16(t-1)\,bsh}{t\,\beta}$$

  3. 两者相除，$b$ 消掉，$s$ 几乎消掉：

    $$\frac{T_\text{comm}}{T_\text{comp}}=\frac{2(t-1)}{9\,(1+\frac{s}{6h})}\cdot\frac{\mathcal F}{h\,\beta}$$

  4. 代入 $\mathcal F=600$ TFLOP/s、$h=8192$、$s=4096$：节点内 NVLink（$\beta\approx 400$ GB/s）、$t=8$ 时比值约 0.26；跨节点 InfiniBand（$\beta\approx 45$ GB/s）、$t=16$ 时约 5，通信时间是计算的 5 倍。

比值随 $t$ 线性增长、随 $h$ 反比下降：模型越宽越能承受大的 $t$。而且这 4 次 all-reduce 都在关键路径上，下一步计算要等它完成。

其他限制：$h$、$a$（以及 GQA 的 KV 头数）都要能被 $t$ 整除；每张卡上的矩阵乘变窄，$t$ 大时单卡效率也下降。能做的优化是把 all-gather / reduce-scatter 拆成小块，和相邻的矩阵乘流水重叠（Megatron-Core 配合 Transformer Engine 的 TP 通信重叠、PyTorch 的 async TP），这要求先用下一节的序列并行把 all-reduce 拆开。NVLink 域更大的机器（如 72 卡一个 NVLink 域的 GB200 NVL72）上，TP 也可以超过 8。

序列并行：把 TP 没切的部分也切开

序列并行（Megatron 的 sequence parallelism，SP）在 TP 区域之外的 LayerNorm、dropout、残差这几段，沿序列维把激活切成 $t$ 份，每张卡只存、只算 $s/t$ 个 token。它总是和 TP 一起开，用同一个 TP 组。

同名不同物

DeepSpeed-Ulysses 和 Ring Attention 也常被叫作「序列并行」，它们切的是注意力本身、为长序列服务，见Ulysses 和上下文并行。这一节只讲 Megatron 的 SP。

  1. 只开 TP 时，$g$ 的 all-reduce 之后每张卡都有完整的 $bs\times h$ 激活。LayerNorm、dropout、残差在 $t$ 张卡上重复算、重复存，这部分激活不随 $t$ 减少。

  2. ring all-reduce 本来就是两步（见集合通信）：

    $$\text{all-reduce}=\text{reduce-scatter}\ \to\ \text{all-gather}$$

  3. 把两步拆开、中间夹上 LayerNorm 和 dropout：行切层之后先 reduce-scatter（求和的同时沿序列切开），在 $s/t$ 个 token 上做 dropout、残差、下一个 LayerNorm，进入下一个列切层前再 all-gather。新的共轭算子：

    $$\begin{aligned}g&:\ \text{前向 all-gather，反向 reduce-scatter}\\ \bar g&:\ \text{前向 reduce-scatter，反向 all-gather}\end{aligned}$$

  4. 每层通信从 4 次 all-reduce 变成 4 次 all-gather + 4 次 reduce-scatter，字节数相同。

激活显存

按 Korthikanti et al. (2022) 的计数（16 位激活、1 字节 dropout mask，单层、一个 micro-batch，各项来源见显存账），一层要存 $sbh(34+5as/h)$ 字节，其中 $10sbh$ 在 TP 区域之外，$24sbh$ 是各线性层与 GeLU 的输入等，$5as^2b$ 是注意力分数、softmax 和 dropout：

配置每层激活（字节）
无并行$\displaystyle sbh\Big(34+\frac{5as}{h}\Big)$
TP$\displaystyle sbh\Big(10+\frac{24}{t}+\frac{5as}{ht}\Big)$
TP + SP$\displaystyle \frac{sbh}{t}\Big(34+\frac{5as}{h}\Big)$
TP + SP + 选择性重计算$\displaystyle \frac{34\,sbh}{t}$

选择性重计算只重算注意力里的 softmax、dropout 和乘 $V$ 那一段：这部分激活大（$\propto s^2$）而 FLOPs 少。FlashAttention 本来就不存 $s\times s$ 的矩阵、反向时重算（见 FlashAttention 的反向），用了它 $5as^2b$ 这一项自然消失。开 SP 后，进入列切层的完整输入也不存：只存自己那 $s/t$ 段，反向时再 all-gather 一次，和梯度计算重叠。

易错

开 SP 后，LayerNorm（RMSNorm）的权重每张卡只看到 $s/t$ 个 token，算出的梯度是部分和，必须在 TP 组内 all-reduce；只开 TP 时每张卡看到全部 token，梯度本来就相同。漏掉这一步，各卡的 LayerNorm 权重会慢慢漂开。

流水线并行与 GPipe 的气泡

流水线并行（pipeline parallelism，PP）把 $L$ 层按顺序切成 $p$ 段（stage），第 $i$ 段放在第 $i$ 张卡上；一个 batch 再切成 $m$ 个 micro-batch，像流水线一样依次流过各段。段与段之间只用点对点 send / recv 传激活（前向）和激活的梯度（反向）。

记号
符号含义单位
$p$流水线段数（stage 数）标量
$i$stage 编号，$0\le i\le p-1$—
$m$一个 batch 的 micro-batch 数标量
$t_f,\ t_b$一个 micro-batch 在一个 stage 上的前向、反向时间（$t_b\approx 2t_f$）s
$v$交错调度里每张卡上的块数（虚拟 stage 数）标量

  1. GPipe 先让 $m$ 个 micro-batch 全部做完前向，再全部做反向。第 $j$ 个 micro-batch 在 stage $i$ 上最早在 $(i+j)\,t_f$ 开始前向。

  2. 最后一个 micro-batch 在最后一段做完前向的时刻是 $(m+p-1)\,t_f$；反向对称，再花 $(m+p-1)\,t_b$：

    $$T=(m+p-1)(t_f+t_b)$$

  3. 每张卡真正干活的时间是 $m(t_f+t_b)$，其余是空等，叫气泡（bubble）：

    $$\text{气泡率}=\frac{T-m(t_f+t_b)}{T}=\frac{p-1}{m+p-1}$$

  4. Megatron 的论文用「气泡时间 / 理想时间」衡量，写成 $\frac{p-1}{m}$，两种写法在 $m\gg p$ 时一致。

要压低气泡就得加大 $m$，但全局 batch $=m\times b\times(\text{数据并行份数})$ 是训练超参数，不能随便放大；GPipe 还要同时存下 $m$ 个 micro-batch 的激活。下一节的 1F1B 解决后一个问题。

1F1B 与交错调度

1F1B：气泡不变，显存有上限

  1. stage $i$ 先做 $p-i-1$ 个前向（warm-up），之后前向、反向一个隔一个（steady），最后把剩下的 $p-i-1$ 个反向做完（cool-down）。

  2. 一个 micro-batch 的激活从前向开始存，到它的反向做完才释放。稳态里 stage $i$ 同时在途的 micro-batch 数是

    $$n_i=p-i$$

  3. stage $i$ 有 $L/p$ 层，激活显存 $\propto n_i\cdot\frac{L}{p}$。第一段最多，正好是 $L$ 层的量，与 $m$ 无关；GPipe 是 $m\cdot\frac{L}{p}$。

  4. 总时长 $T$ 和 GPipe 相同：1F1B 没有减少气泡，但显存不再随 $m$ 增长，于是 $m$ 可以放心加大。

1F1B 来自 PipeDream；带每步一次同步刷新（flush）的版本叫 PipeDream-Flush，是 Megatron 默认的非交错调度。

交错 1F1B：每张卡放 $v$ 块

  1. 把模型切成 $pv$ 块，每块 $\frac{L}{pv}$ 层，第 $i$ 张卡放第 $i,\ i+p,\ \dots,\ i+(v-1)p$ 块（从 0 数）。例如 $L=16$、$p=4$、$v=2$ 时卡 0 放第 1–2 层和第 9–10 层。

  2. 每块的前向、反向时间缩成 $t_f/v$、$t_b/v$，填充和排空流水线时等的是一块而不是一整段：

    $$\text{气泡时间}=\frac{(p-1)(t_f+t_b)}{v},\qquad \frac{\text{气泡}}{\text{理想}}=\frac{p-1}{vm}$$

  3. 代价一：每个 micro-batch 要在卡之间来回 $v$ 圈，点对点通信量变成 $v$ 倍。代价二：Megatron 最初的实现要求 $m$ 是 $p$ 的整数倍（本页的图也这样取）。

  4. 代价三是显存。Megatron 在卡 $i$ 上的 warm-up 块数是 $2(p-i-1)+(v-1)p$，卡 0 的峰值在途块数为 $vp+p-1$，每块 $\frac{L}{pv}$ 层：

    $$\text{卡 0 激活}\ \propto\ (vp+p-1)\cdot\frac{L}{pv}=L\Big(1+\frac{p-1}{pv}\Big)\ \text{层}$$

    比非交错的 $L$ 层多一点，$v$ 越大越接近 $L$。

Zero Bubble 与 DualPipe

前面的调度都把反向当成一整块。其实反向里只有一半在关键路径上。

  1. 以线性层 $Y=XW$ 为例（$X\in\mathbb R^{n\times d_\text{in}}$，$W\in\mathbb R^{d_\text{in}\times d_\text{out}}$），反向要算两个梯度：

    $$\underbrace{\nabla_X=\nabla_Y\,W^\top}_{\text{B：上一段马上要用}}\qquad \underbrace{\nabla_W=X^\top\,\nabla_Y}_{\text{W：只有 optimizer step 才用}}$$

  2. B 算完就能把 $\nabla_X$ 发给上一段，W 可以推迟到任何空闲时刻，只要在本步 optimizer step 之前做完；同一步内所有前向、反向用的都是旧权重，推迟不改变数值。

  3. 设 $T_F,T_B,T_W$ 分别是一块 F、B、W 的时间（完整反向是 $T_B+T_W$）。ZB-H1 沿用 1F1B 的骨架，把 W 往后挪去填尾部的空。每张卡的气泡：

    $$\begin{aligned}\text{1F1B}&:\ (p-1)(T_F+T_B+T_W)\\ \text{ZB-H1}&:\ (p-1)(T_F+T_B-T_W)\end{aligned}$$

    $T_F=T_B=T_W$ 时是 1F1B 的三分之一，峰值显存不变（每张卡在途 $p$ 个 micro-batch）。

  4. ZB-H2 在 warm-up 里多做前向（stage $i$ 做 $2(p-i)-1$ 个），把卡 0 中间等第一个 B 的空也填上，每张卡从开始到结束不再有空闲，代价是在途 micro-batch 增到 $2p-1$。剩下首尾的三角形要靠去掉 optimizer step 前的全局同步才能和下一步咬合：论文的做法是先乐观地更新，再事后检查（梯度裁剪、NaN / Inf），检查不过就回滚。

论文还给了按实测 $T_F,T_B,T_W$ 和显存上限自动搜索调度的算法（显存上限为 $p$ 和 $2p$ 个 micro-batch 时分别叫 ZB-1p、ZB-2p）。同一组作者后来把调度拆成重复的「构建块」，用 V 形放置（每张卡放首尾对称的两块）得到一族调度：V-Half 把激活显存降到 1F1B 的约 1/2，V-Min 降到约 1/3（气泡随 $m$ 增长），V-ZB 在与 1F1B 相当的显存下做到零气泡。

DualPipe

DeepSeek-V3 用的 DualPipe 是双向流水线：micro-batch 同时从两端灌入，每张卡放第 $i$ 段和第 $p-1-i$ 段，参数存两份。它把一个方向的前向块和另一个方向的反向块配成一对，两块的计算与通信（MoE 的 all-to-all、PP 的 send/recv）互相重叠，见专家并行的通信重叠。DualPipe 仓库 README 给的对照（$F$、$B$、$W$ 是一块前向、一块完整反向、一块权重梯度的时间，$F\&B$ 是一对互相重叠的前向和反向块的时间）：

调度气泡参数激活（micro-batch 数）
1F1B$(PP-1)(F+B)$1×$PP$
ZB1P$(PP-1)(F+B-2W)$1×$PP$
DualPipe$(\frac{PP}{2}-1)(F\&B+B-3W)$2×$PP+1$

参数存两份的代价后来被去掉了：Sea AI Lab 把 DualPipe「对半切」成单向的 V 形调度，参数 1×，DeepSeek 以 DualPipeV 的名字收进了 DualPipe 仓库（截至 2026-11）。

框架里在哪

Megatron-Core 支持 1F1B 和交错 1F1B；PyTorch 的 torch.distributed.pipelining 提供 ScheduleGPipe、Schedule1F1B、ScheduleInterleaved1F1B、ScheduleLoopedBFS，以及拆分 B / W 的 ScheduleInterleavedZeroBubble、ScheduleZBVZeroBubble（2.7 起的源码里都有）。Zero Bubble 的 Megatron 实现在 sail-sg 的仓库里。

各 stage 的显存不均

同样是 $L/p$ 层，各 stage 的显存差得很多，原因有两个：

  • 激活：1F1B 下 stage $i$ 在途 $p-i$ 个 micro-batch，卡 0 的激活是最后一张卡的 $p$ 倍。
  • 词表层：输入 embedding 在第一段，输出层和 loss 在最后一段，各有 $Vh$ 个参数；大词表（$V\gt 10^5$）时一个词表层相当于一两个 Transformer 层，最后一段还要存 $bs\times V$ 的 logits。

常见的平衡办法：

  • 不均匀切层：首尾两段少放一两层。Megatron-Core 的 --pipeline-model-parallel-layout 可以逐段写明放什么，例如文档里 DeepSeek-V3 在 PP16、VPP2 下的布局 "Et*3|(tt|)*29,m|L"（E = embedding，t = Transformer 层，m = MTP 层，L = loss）。
  • 换调度：V 形放置让每张卡同时有一个靠前、一个靠后的块，激活更均匀；交错调度的卡 0 只比 $L$ 层多一点。
  • 激活卸载：PipeOffload（ICML 2025）发现 1F1B 里多数在途激活要等很久才用到，可以先搬到 CPU 内存，通常至少一半、有时全部都能卸载而几乎不掉速。

Narayanan et al. (2021) 的经验：TP 用到一台机器的卡数（通常 8）为止，再大的模型用 PP 跨机器扩展；同时开 TP 时，stage 之间要传的激活在 TP 组内本来是重复的，可以让每张卡只经自己的网卡发其中 $1/t$ 的数据，到对面再用 NVLink all-gather 拼回来。TP、PP 和数据并行、上下文并行、专家并行怎样排进一个集群、怎样选各维的大小，见多维组合和配置算例。

上下文并行：Ring Attention

上下文并行（context parallelism，CP）把一条序列按 token 切成 $p_\text{cp}$ 段分给 $p_\text{cp}$ 张卡，每张卡只存自己那段的激活。线性层、MLP、LayerNorm 都是逐 token 的，各算各的；只有注意力要用到全部 token 的 K、V，于是 K、V 在卡之间传。

激活显存与序列长 $s$ 成正比（显存账）。TP + SP 也能把激活切 $p_\text{tp}$ 份（序列并行），但 $p_\text{tp}$ 受头数和节点内卡数限制；128K 以上的序列还要再沿序列切一维，这一维就是 CP。

记号
符号含义形状 / 单位

分块注意力怎么合并

  1. 卡 $r$ 要算 $\mathrm{softmax}(Q_rK^\top/\sqrt d)\,V$。把 $K,V$ 按卡分成 $p_\text{cp}$ 块，每块单独算分数：

    $$S_{rj}=Q_rK_j^\top/\sqrt d,\qquad j=0,\dots,p_\text{cp}-1$$

  2. 每来一块，用 online softmax 更新行最大值和指数和（推导见 FlashAttention 一页）：

    $$m'=\max\!\big(m,\ \mathrm{rowmax}\,S_{rj}\big),\qquad \ell'=e^{m-m'}\ell+\mathrm{rowsum}\,e^{S_{rj}-m'}$$

  3. 输出也先把旧值按新的最大值缩放，再加上新块的贡献：

    $$O'=e^{m-m'}O+e^{S_{rj}-m'}V_j$$

  4. 所有块处理完再归一化。合并与块到达的顺序无关，所以 K/V 块可以按任意顺序来：

    $$\mathrm{Attn}_r=\mathrm{diag}(\ell)^{-1}O$$

Ring Attention（Liu et al. 2023）把 $p_\text{cp}$ 张卡连成环：第 $t$ 步卡 $r$ 用手上的 $K_{(r-t)\bmod p_\text{cp}},V_{(r-t)\bmod p_\text{cp}}$ 计算，同时把这块发给卡 $r+1$、从卡 $r-1$ 收下一块。$p_\text{cp}$ 步后每张卡见过全部 K/V，每卡只多一到两块 K/V 的缓冲。反向同理，$\mathrm{d}K,\mathrm{d}V$ 跟着 K/V 一起绕环回到原主。

因果掩码下的负载

因果掩码下 Q 块 $i$ 只看 K/V 块 $j\le i$。按连续段切时，卡 0 只有半块要算，最后一张卡要算满。环上每一步都要等最慢的卡，所以总耗时是「每步最大值」之和。把序列切成 $2p_\text{cp}$ 小块，记一个小块对的计算量为 1、对角块为 $\tfrac12$：

  1. Q 小块 $i$ 的总计算量：

    $$w_i=\sum_{j\lt i}1+\tfrac12=i+\tfrac12$$

  2. 连续切：卡 $r$ 拿小块 $2r,2r+1$。第 $t\ge1$ 步卡 $r\ge t$ 拿到的 K/V 全在左下方，四个小块对全要算；卡 $r\lt t$ 拿到的全被掩掉。每步最大值是 4，第 0 步是 2：

    $$T_\text{连续}=2+4(p_\text{cp}-1)=4p_\text{cp}-2$$

  3. zigzag：卡 $r$ 拿小块 $r$ 和 $2p_\text{cp}-1-r$（首尾配对）。收到卡 $j\ne r$ 的 K/V（小块 $j,\ 2p_\text{cp}-1-j$）时，四个小块对的计算量是：

    $$[\,j\lt r\,]+0+1+[\,j\gt r\,]=2$$

    第 0 步是 $\tfrac12+0+1+\tfrac12=2$。每步每卡都恰好是 2。

  4. 理想耗时是总量平均到 $p_\text{cp}$ 张卡：$\sum_r(4r+2)/p_\text{cp}=2p_\text{cp}$。zigzag 正好达到，连续切是它的

    $$\frac{4p_\text{cp}-2}{2p_\text{cp}}=2-\frac1p_\text{cp}\ \text{倍}$$
实现

Megatron-Core 的 CP 用的就是首尾配对，通信走环形 P2P，也可以用 --cp-comm-type 换成 all-gather、all-to-all（即下一节的 Ulysses）或两者分层组合。Llama 3 的 CP 同样切 $2p_\text{cp}$ 块首尾配对，但不绕环，而是先 all-gather 整条 K/V 再算本地的 Q：GQA 下 K/V 只有 Q 的 $a_{kv}/a$ 那么大，一次收齐也不贵。Striped Attention（Brandon et al. 2023）用另一种均衡：按 token 轮流分（卡 $r$ 拿第 $r,\ r+p_\text{cp},\ r+2p_\text{cp},\dots$ 个 token）。

通信能不能藏起来

  1. 每一步每卡算一个 $c\times c$ 块的 $QK^\top$ 和 $PV$，各 $2c^2h$ FLOPs：

    $$t_\text{comp}=\frac{4c^2h}{F}$$

  2. 同时发出一块 K 和 V（BF16，每元素 2 字节）：

    $$t_\text{comm}=\frac{2\cdot 2\,c\,h_{kv}}{B}=\frac{4c\,h_{kv}}{B}$$

  3. $t_\text{comp}\ge t_\text{comm}$ 时通信被完全重叠：

    $$c\ \ge\ \frac{F}{B}\cdot\frac{h_{kv}}{h}$$

计算随 $c^2$ 涨，通信随 $c$ 涨，块够长就藏得住。MHA 时 $h_{kv}=h$，条件就是原文的 $c\ge F/B$。跨节点 IB 每卡约 50 GB/s，比节点内 NVLink 慢近一个数量级，阈值也大近一个数量级。

DeepSpeed-Ulysses 与 USP

Ulysses（Jacobs et al. 2023）也沿序列切，但在注意力前用一次 all-to-all 把「每卡 $s/p_\text{cp}$ 个 token、全部 $a$ 个头」换成「每卡全部 $s$ 个 token、$a/p_\text{cp}$ 个头」，各卡独立做完整的注意力，再用一次 all-to-all 换回来。

注意力在头与头之间互不相干，换成按头切以后，每张卡上就是一次普通的单卡注意力：直接调用 FlashAttention，掩码、变长都不用改。all-to-all 的语义见 集合通信。

  1. 每卡持有 Q、K、V 各 $\frac{s}{p_\text{cp}}\times h$，换完是 $s\times\frac{h}{p_\text{cp}}$。每卡留下 $1/p_\text{cp}$，其余发给另外 $p_\text{cp}-1$ 张卡：

    $$\text{每卡发送}=\frac{p_\text{cp}-1}{p_\text{cp}}\cdot\frac{3sh}{p_\text{cp}}$$

  2. 注意力输出再换回来，又是 $\frac{p_\text{cp}-1}{p_\text{cp}}\cdot\frac{sh}{p_\text{cp}}$。每层前向合计约：

    $$\frac{4sh}{p_\text{cp}}\qquad(\text{GQA 时为 } (2h+2h_{kv})\,s/p_\text{cp})$$

  3. 对比 Megatron-SP：每层前向 2 次 all-gather 加 2 次 reduce-scatter，每次每卡约 $\frac{p_\text{cp}-1}{p_\text{cp}}sh$，合计约 $4sh$，不随 $p_\text{cp}$ 减少。原文分别记作每条链路 $4Nh/P$ 和 $4Nh$（$N$ 为序列长）：$s$ 与 $p_\text{cp}$ 同比增大时，Ulysses 的通信量不变。

并行度上限

Ulysses 按头切，$p_\text{cp}$ 不能超过头数且要整除头数。GQA 下 K/V 只有 $a_{kv}$ 个头（常见为 8），$p_\text{cp}\gt a_{kv}$ 时 K/V 头要复制。all-to-all 在注意力前后各一次，处在关键路径上，难以和计算重叠，组内需要全连通的高带宽，跨节点后掉得快。

USP：两种合起来

USP（Fang & Zhao 2024）把序列并行组排成 $p_u\times p_r$ 两维，$p_\text{cp}=p_u\,p_r$：$p_u$ 那一维走 Ulysses，放在节点内；$p_r$ 那一维走 Ring，可以跨节点。Ulysses 受头数限制但通信量随 $p_\text{cp}$ 下降，Ring 不受头数限制但要靠块长掩盖通信，两者互补。

MoE 回顾：路由与负载均衡

混合专家层（mixture of experts，MoE）把 FFN 换成 $E$ 个结构相同的专家 FFN 和一个路由器；每个 token 只送进得分最高的 $k$ 个专家。参数量随 $E$ 涨，每个 token 的计算量只随 $k$ 涨。

记号
符号含义形状
$E,\ k$路由专家数；每个 token 激活的专家数标量
$\mathbf u_t$第 $t$ 个 token 进入 MoE 层的隐状态$\mathbb R^{h}$
$\mathbf e_i$专家 $i$ 的路由向量$\mathbb R^{h}$
$s_{i,t},\ g_{i,t}$亲和度；门控权重（没选中为 0）标量
$T,\ n_i,\ \bar n$一批 token 数；分到专家 $i$ 的 token 数；均值 $kT/E$标量
$b_i$专家 $i$ 的路由偏置，只在选专家时用标量
$h_e$专家 FFN 的中间维标量

  1. 亲和度：Switch、Mixtral 用 softmax，DeepSeek-V3 用 sigmoid：

    $$s_{i,t}=\sigma(\mathbf u_t^\top\mathbf e_i)$$

  2. 取前 $k$ 个，权重在选中的专家里归一化：

    $$g_{i,t}=\frac{s_{i,t}\,[\,i\in\mathrm{TopK}_t\,]}{\sum_{j\in\mathrm{TopK}_t}s_{j,t}}$$

  3. 输出是专家输出的加权和，加残差（有共享专家时再加共享专家的输出）：

    $$\mathbf h_t=\mathbf u_t+\sum_{i=1}^{E}g_{i,t}\,\mathrm{FFN}_i(\mathbf u_t)$$

  4. 固定形状的实现给每个专家一个容量，容量因子 $\mathrm{CF}\ge1$ 留余量；超出容量的 token 被丢弃，只走残差。不设容量的叫 dropless：

    $$C=\mathrm{CF}\cdot\frac{kT}{E}$$

路由器会自我强化：被选得多的专家学得更好、得分更高、更常被选。负载不均有两个代价：容量满了丢 token；在专家并行下，收 token 最多的那张卡决定整层的耗时。

辅助损失

Switch Transformer（Fedus et al. 2021，$k=1$）加一项

$$\mathcal L_\text{aux}=\alpha\,E\sum_{i=1}^{E}f_i\,P_i,\qquad f_i=\frac{n_i}{T},\quad P_i=\frac1T\sum_{t}s_{i,t}$$

$f_i$ 不可导，梯度经 $P_i$ 把概率从热门专家上推开；完全均匀时取最小值 $\alpha$。原文 $\alpha=10^{-2}$。系数大了会和语言模型损失抢梯度，小了压不住。

无辅助损失：只调偏置

Wang et al.（2024）和 DeepSeek-V3 给每个专家一个偏置 $b_i$，只在选专家时加上，门控权重仍用原来的 $s_{i,t}$：

$$\mathrm{TopK}_t=\operatorname*{TopK}_i\,\big(s_{i,t}+b_i\big),\qquad b_i\leftarrow b_i+\gamma\,\mathrm{sign}\big(\bar n-n_i\big)$$

每步结束后，超载专家的偏置减 $\gamma$，欠载的加 $\gamma$。偏置不产生梯度，不和主损失争方向。DeepSeek-V3 另外保留了一个系数很小的序列级平衡损失，防止单条序列内部极端不均。

专家并行：两次 all-to-all

专家并行（expert parallelism，EP）把 $E$ 个专家分到 EP 组的 $p_\text{ep}$ 张卡上，每卡存 $E/p_\text{ep}$ 个。注意力等其余部分照常按数据并行，token 分散在各卡上；MoE 层前用 all-to-all 把 token 送到选中专家所在的卡（dispatch），算完再用 all-to-all 送回（combine）。

  1. 路由：每卡对本地 $T$ 个 token 算 TopK。
  2. 重排（permute）：按目标卡把 token 复制 $k$ 份、排成连续段；各卡先交换「我要发给你几个」的计数。
  3. dispatch：all-to-all 发出 token 的隐状态。
  4. 专家计算：本卡各专家收到的 token 数不同，用 grouped GEMM 一次算完。
  5. combine：all-to-all 把输出送回原卡，按 $g_{i,t}$ 加权求和、还原顺序。

通信量与计算量

  1. 均匀路由时每个 token 的 $k$ 份副本有 $(p_\text{ep}-1)/p_\text{ep}$ 要出卡。每卡 dispatch 发送：

    $$V_\text{disp}=\frac{p_\text{ep}-1}{p_\text{ep}}\,k\,T\,h\ \ \text{个元素}$$

  2. combine 一样多；反向再各来一次。每层每个训练步共 $4V_\text{disp}$。

  3. 专家是 SwiGLU（三个 $h\times h_e$ 矩阵），每个 token 副本的前向计算 $6h\,h_e$ FLOPs。前向的计算时间比 dispatch 时间（BF16，忽略 $(p_\text{ep}-1)/p_\text{ep}$）：

    $$\frac{6kTh\,h_e/F}{2kTh/B}=\frac{3\,h_e\,B}{F}$$

这个比值与 $k$、$T$ 都无关，只看专家多宽、网络多快。细粒度专家的 $h_e$ 小：DeepSeek-V3 的 $h_e=2048$，按 H800 的 BF16 稠密峰值约 989 TFLOPS、IB 每卡约 50 GB/s 算，比值约 0.3，通信时间是计算的 3 倍以上。这就是下面那些通信优化的由来。

EP 外面还有一维：专家参数在 $\text{world}/(p_\text{etp}\,p_\text{ep}\,p_\text{pp})$ 张卡之间复制，叫专家数据并行（EDP），专家的梯度在这一组里同步，非专家参数照常在 DP 组里同步（数据并行）。

专家张量并行与 parallel folding

专家张量并行（expert tensor parallelism，ETP）在 EP 之外，再把每个专家的 FFN 按 Megatron 的列切 / 行切分到 $p_\text{etp}$ 张卡上（张量并行），代价是专家里多一次 all-reduce 或 reduce-scatter。

专家越细，ETP 越不划算：$h_e=2048$ 切 8 份后每卡只剩 256 列，GEMM 效率低，还多一次集合通信。Megatron-Core 的 MoE 指南建议专家层优先用 EP 而不是 TP（例：Mixtral 8×7B 上 EP8×TP1 快于 EP4×TP2）；EP 等于专家数时，本地连重排都省了。

parallel folding

以前常见的做法是 EP 组从 DP 维里划出来，专家层沿用注意力层的 TP。MoE Parallel Folding（Liu et al. 2025，Megatron-Core）把两类层的切法解耦：注意力层用 $\text{TP}\times\text{CP}\times\text{DP}\times\text{PP}$，MoE 层用 $\text{ETP}\times\text{EP}\times\text{EDP}\times\text{PP}$，只要求两者的 PP 相同、总卡数相同：

$$p_\text{tp}\,p_\text{cp}\,p_\text{dp}=p_\text{etp}\,p_\text{ep}\,p_\text{edp}$$

EP 可以「折叠」到注意力层 TP、CP 维所占的那些卡上，所以 EP 组能整个落在一个 NVLink 域里。原文附录的例子：注意力层 TP2·CP2·DP2，MoE 层 ETP1·EP8·EDP1，8 张卡每张一个专家。下面 多维组合 一节的图可以切换两种层看同一批卡的分组。

EP 的通信：限节点路由、DeepEP 与重叠

跨节点的 all-to-all 走 IB / RoCE，每卡约 50 GB/s；节点内 NVLink 快几倍（拓扑）。DeepSeek-V3 从三个方向压这部分开销。

限节点路由

每个 token 最多发往 $M$ 个节点：先按「每个节点上得分最高的 $k/M$ 个专家的亲和度之和」挑出 $M$ 个节点，再只在这些节点的专家里取 TopK。DeepSeek-V3 每层 256 个路由专家分在 8 个节点上，$k=8$，$M=4$。token 经 IB 到达目标节点后再用 NVLink 转给节点内各目标卡，同一节点上的多个专家只走一次 IB。

原文按带宽算了一笔账：IB 与 NVLink 约为 50 : 160 GB/s，一个 token 平均在每个节点内选 3.2 个专家时 NVLink 转发不会成为瓶颈，所以同样的通信代价下最多可以选 $4\times3.2\approx13$ 个专家，而实际只用了 8 个。

DeepEP

DeepEP 是 DeepSeek 2025 年开源的 dispatch / combine 通信库。normal 内核面向训练和推理 prefill，节点内走 NVLink、节点间走 RDMA，追求吞吐；low-latency 内核面向解码，只用 RDMA，并提供基于 hook 的通信计算重叠，不占用 SM。

计算通信重叠

dispatch / combine 很难和本层计算重叠：专家要等 token 到齐才能算。DeepSeek-V3 的 DualPipe 让两个方向的微批交错，一个微批的 all-to-all 与另一个微批的计算同时进行（Zero Bubble 与 DualPipe）。DeepSeek-V3 的训练配置：2048 张 H800，PP16、EP64（跨 8 个节点）、ZeRO-1 数据并行，没有用 TP。

多维组合：把各维排进集群

device mesh 把 world 张卡排成一个多维数组，每一维对应一种并行；沿某一维变化、其余坐标都固定的那些卡，就是这一维的一个通信组。

维度的顺序决定谁和谁相邻。rank 号连续的 8 张卡通常在同一个节点上，所以排在最内层（变化最快）的维度落在 NVLink 里。Megatron-Core 默认顺序是 tp-cp-ep-dp-pp，tp 变化最快。注意力层的网格（EP 维为 1）对应

$$\text{rank}=i_\text{tp}+p_\text{tp}\Big(i_\text{cp}+p_\text{cp}\big(i_\text{dp}+p_\text{dp}\,i_\text{pp}\big)\Big)$$

MoE 层的网格把 $(i_\text{tp},i_\text{cp},i_\text{dp})$ 换成 $(i_\text{etp},i_\text{ep},i_\text{edp})$，PP 维相同。排序依据是每一维的通信有多大、多频繁、能不能藏：

维度通信频率与能否重叠放在哪
TP / SP激活的 all-reduce 或 reduce-scatter + all-gather每层前反向各数次，在关键路径上最内层，节点内
CPK/V 的环形 P2P 或 all-gather；Ulysses 是 all-to-all每层一次，Ring 可与注意力重叠节点内，或紧挨着 TP
EPtoken 的两次 all-to-all每个 MoE 层前后各一次，难重叠尽量节点内；跨节点要限节点路由等优化
DP / FSDP梯度 all-reduce 或 reduce-scatter（FSDP 还有参数 all-gather）每步一次（FSDP 每层），可与反向重叠跨节点
PP相邻 stage 之间 P2P 传激活量小最外层，跨节点

PyTorch 里用 DeviceMesh 描述同一件事。init_device_mesh 按行优先排列，最后一维变化最快，所以 tp 写在最后：

from torch.distributed.device_mesh import init_device_mesh
mesh = init_device_mesh("cuda", (2, 2, 2, 2), mesh_dim_names=("pp", "dp", "cp", "tp"))
tp_group = mesh["tp"]        # 本卡所在的 TP 子网格
dp_cp = mesh["dp", "cp"]     # 取两维的子网格，例如交给 FSDP 一起切

TorchTitan（Liang et al. 2024）就是在 DeviceMesh 和 DTensor 上组合 FSDP2、TP、PP、CP 的参考实现。

怎么选配置

  1. 先让一层放得下：一个微批的激活或一层的权重单卡放不下时开 TP，最多到节点内卡数，且整除头数。
  2. 再让模型状态放得下：开 PP（层数整除 PP），或用 ZeRO-3 / FSDP 把参数也切掉（ZeRO）。
  3. 序列太长开 CP，MoE 开 EP：EP 尽量放在节点内，跨节点时配合限节点路由和重叠。
  4. 剩下的卡全给 DP，配 ZeRO-1（分布式优化器）；全局 batch 要能被 DP 整除。
  5. 有 PP 时看气泡：每条流水线的微批数 $m$ 至少是 $p_\text{pp}$ 的几倍，气泡占比 $\frac{p_\text{pp}-1}{m+p_\text{pp}-1}$ 才小（流水线并行）。

符号含义单位

  1. 模型状态：TP 和 PP 把参数切成 $p_\text{tp}p_\text{pp}$ 份；BF16 参数与梯度每参数 4 字节；FP32 主权重和 Adam 的 $m,v$ 共 12 字节，分布式优化器在 DP×CP 组里再切（CP 各卡持有同样的参数）：

    $$M_\text{state}=\frac{\\Psi}{p_\text{tp}\,p_\text{pp}}\Big(4+\frac{12}{p_\text{dp}\,p_\text{cp}}\Big)$$

  2. 每层每个微批的激活：开 TP + SP 与选择性重计算时约 $34\,sbh$ 字节（Korthikanti et al.，标准 GPT 块），TP 和 CP 各切一刀：

    $$a_\text{layer}=\frac{34\,s\,b\,h}{p_\text{tp}\,p_\text{cp}}$$

  3. 1F1B 下第一个 stage 同时存着 $\min(p_\text{pp},m)$ 个微批的激活，每个微批覆盖 $L/p_\text{pp}$ 层：

    $$M_\text{act}=\frac{L}{p_\text{pp}}\cdot\min(p_\text{pp},m)\cdot a_\text{layer}$$

自测

ZeRO-3 / FSDP 的 $3\Psi$ 是哪三次？哪一次可以省，代价是什么？

前向 all-gather、反向 all-gather、梯度 reduce-scatter。设 reshard_after_forward=False 可以省掉反向那次 all-gather，代价是前向后完整参数一直留到反向，显存退回接近 ZeRO-2。

4 节点 × 8 卡、Ψ = 13B，HSDP 和全局 FSDP 每卡模型状态各多少？每节点跨节点流量呢？

显存：$16\Psi/8=26$ GB 对 $16\Psi/32=6.5$ GB。$M=2\Psi=26$ GB，跨节点：HSDP $2\cdot\tfrac34M=39$ GB，FSDP $3\cdot\tfrac34M=58.5$ GB。

开 TP（t = 8）时，一个 Transformer 层前向加反向有几次集合通信，每次多大？开 SP 后呢？

4 次 all-reduce（前向注意力、MLP 各一次，反向各一次），每次 $bsh$ 个元素。开 SP 后变成 4 次 all-gather 加 4 次 reduce-scatter，总字节数不变。

p = 8、m = 32 时 GPipe 的气泡率是多少？改用 v = 2 的交错 1F1B 呢？

GPipe：$\frac{7}{39}\approx 18\%$。交错：气泡时间缩成 $\frac{1}{2}$，气泡率 $\frac{7}{2\cdot 32+7}=\frac{7}{71}\approx 9.9\%$，代价是点对点通信翻倍、卡 0 激活多到 $L(1+\frac{7}{16})$ 层。

Zero Bubble 推迟计算 $\nabla_W$，为什么不影响训练结果？

$\nabla_W$ 只在本步的 optimizer step 里用到；本步所有前向和 $\nabla_X$ 都用旧权重，什么时候算 $\nabla_W$ 不改变它的值，只要在 step 之前算完。

Ulysses 的并行度为什么有上限？64 个 Q 头、8 个 K/V 头时怎么办？

它在注意力时按头切，$p_\text{cp}$ 不能超过头数。Q 有 64 头，但 K/V 只有 8 头，$p_\text{cp}\gt8$ 时 K/V 头得复制到多张卡。再要扩展就用 USP：节点内 Ulysses、节点间 Ring。

专家并行的 dispatch 为什么用 all-to-all，而不是 all-gather？

每个 token 只需要去 $k$ 个专家所在的卡，各卡发给各卡的数据不同；all-gather 会把所有 token 发给所有卡，通信量放大约 $p_\text{ep}/k$ 倍。

为什么 TP 放最内层、PP 放最外层？

TP 每层前反向都要对激活做集合通信，且在关键路径上，只有 NVLink 撑得住；PP 只在相邻 stage 之间传一个微批的激活，量小，跨节点也无妨。
